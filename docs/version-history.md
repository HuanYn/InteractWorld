# 自训 Demo：版本变化、画面结果与定量对照

整理日期：2026-09-13。当前展示选择是 **Action R005 step1040 + window6（6+6+3 秒）**。后续实验有更低的单例像素误差，也有明确的失败视频；版本号更大不等于画面更好。视频均来自本项目已有生成结果，未为本页重新训练或生成。

另见[完整四段配对实验](action-control-pairs.md)：复用固定Action1040权重，仅补生成同图文/同seed、不同动作的两组视频，不是新训练版本。[README](../README.md#demo-视频与版本对照)按画面表现选片，不是完整对照或平均质量。下表的历史分数不适用于这些自定义动作样片。

## 如何读版本名

R1 / R2 是早期 LongForcing-lite 的两轮运行修复，不是两套新模型。Action R003 / R004 / R005 / R007 是动作模型实验；Causal R006 是另一条因果适配分支。`step` 是该分支的 optimizer 更新计数：只加载父权重后从 0 开始，与恢复 optimizer、RNG、数据游标后继续训练不同。后面的 `clean60`、`recycling60`、`history-noise20` 按方法和步数命名，不与 R005 / R006 模型版本混用。

`chunked`、`joint61`、`window6`、`6+3+6` 是推理布局；同一 R0051040 权重可用不同布局生成。`native97` 才表示训练窗口由 49 RGB 帧改为连续 97 帧；所选 R0051040 本身仍用 49 帧训练。

## 数据范围

数据来自公开的 ABot-World-Explorer-500h 子集；“500h”是数据集名称，不能写成本项目实际使用了全部 500 小时。已核对的 native97 分支选择 128 个训练 episode，实际缓存 256 个连续 97 帧窗口；这一数量不套用到其他分支。原版固定索引映射只选中其中 201 个缓存窗口，其余 55 个不会随相同索引重跑而出现，噪声与时间步也重复，后续重采样版本针对这些问题修改。

固定 15 秒 RGB 表使用一个 dev 场景 / 起点 / seed42，没有完整验证集均值或跨种子统计。样片中含第三人称人物，不能概括为全是第一人称数据；数据筛选代码保留排除 Minecraft 的规则。早期 LongForcing-lite 示例另用场景与 seed4201，不能与这张固定案例表直接比较。

## 同权重的推理布局：为什么最终选 window6

以下四行都是 **Action R005 step1040**，不是四次新训练。它们使用 seed42、40 步 Euler；分窗后以生成 RGB 末帧重编码续写，没有用真实未来补帧。`joint61` 一次生成 61 latent 对应的 15 秒，是非因果整段生成。

| 布局 | 改动 | 已观察画面 / 选择结果 |
| --- | --- | --- |
| [chunked，5×3 秒](https://huanyn.github.io/InteractWorld/#action-r005-1040-chunked) | 五个 49 RGB 帧窗口续写 | 后段有模糊和形变，末帧人物仍存在；不能说成“原版完全丢人” |
| [joint61，整段 15 秒](https://huanyn.github.io/InteractWorld/#action-r005-1040-joint61) | 同权重改为整段联合推理 | correct RGB MSE 比旧分段低 31.4578%，但抬头响应退步，因此未选为默认 |
| [window6，6+6+3 秒](https://huanyn.github.io/InteractWorld/#action-r005-1040-window6) | 三窗分别 97 / 97 / 49 RGB 帧，去掉重复条件帧后为 241 帧 | 约 7.5 秒抬头、11–12 秒转回俯地的总体响应恢复；所查帧人物和地形保留到末尾，仍有软变形。选为异步 Demo |
| 6+3+6 秒 | 只调整窗口边界，检查后段反馈位置 | 固定案例数值过线，未采用；它的 zero / shuffled 不能作为 6+6+3 的对照 |

上面 `window6` 链接是历史**网页 RGB 首图协议**样片。下表 .035743487 来自另一个**冻结 latent 协议**样片的后续辅助评分；两者输入编码不同，不是同一条视频的分数。网页样片总处理 139.111 秒；冻结样片生成 142.679 秒。它们输出 241 帧、16 FPS，首尾跨度 15 秒、文件时长 15.0625 秒；16 FPS 是播放速度，未达到实时生成。

## 15 秒 RGB 定量表

全部是一个冻结场景 / 起点 / seed42 的诊断，40 步 Euler。评分对解码后全画幅 RGB 先除以 255，在第 120 / 180 / 240 帧（7.5 / 11.25 / 15 秒）分别算 MSE，再按 0.2 / 0.3 / 0.5 加权；越低越好，包含常规视频编码影响。真实未来只在生成后的评分环节读取。三个锚点来自同一视频，**不是三个独立样本**。

## 不能并入 RGB 表的指标

**早期 3 秒 flow 诊断。** R003 dev 正确/零/打乱动作在 σ=0.2 的 MSE 为 .501873195 / .498369604 / .502090871；σ=0.5 为 .241729796 / .242763102 / .241805419；σ=0.8 为 .165347189 / .164851412 / .165343776。R004 在静态文本下相对其匹配基线的 correct 三档均值由 .302834511 降到 .299205547，约 1.1983%；其 σ=0.8 correct .162460342 仍高于 shuffled .162214398。这是未加权 latent flow MSE，不是成片 RGB 误差或控制准确率。

**因果推理耗时。** 同 Causal R0061280 的 sliding-window 总耗时 321.390 秒、latent 生成 281.657 秒、峰值 allocated 12,165,271,552 字节；full-history KV 为 148.546 秒、111.771 秒、20,183,961,088 字节。保留更多历史伴随时间减少和显存增加，历史范围与实现同时变化，不能称为等价算法的单变量提速；两者画质与控制均未通过。这些数字不属于 R005 网页 Demo。

**历史来源诊断。** 同 clean60 权重、同一个 3 秒输入，只改变首块之后的历史来源：首块逐位相同，最后一块 GT-history oracle 的 latent MSE 为 .324608684，自生成历史为 .790737152。它支持该短轨迹对历史误差敏感；oracle 使用真实历史协助，不是可部署 Demo，也不能证明暴露偏差是唯一根因。后续高斯加噪与干净续训两臂都失败，不能独归因于噪声。

## 证据与复现边界

[version-results.json](version-results.json)保存精确数值、模型 SHA256、方法标签和脱敏来源摘要。SHA 来自保留的历史记录；本次没有下载权重或重新计算权重哈希。公开视频是展示/失败例证，评分仍对应历史原始生成视频，不能对附输入栏或展示压缩视频重算后冒称同一原始分数。

本页覆盖主要改动与有证据的代表性 checkpoint，不为每个 optimizer 步伪造独立视频。R1/R2 无独立固定输入成片；R003 这里只公开实际 3 秒片段；部分后续分支缺少 RGB 动作三对照。当前仍缺所选网页协议的完整同配置动作对照，以及更多独立场景、起点、种子和相机响应测量；没有可靠方向控制、任意长稳定生成或实时性能的结论。
