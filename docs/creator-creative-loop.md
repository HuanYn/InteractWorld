# 用自然语言修改已生成视频

这是 **视频创作 Creator**，不是互动影游／游戏导航环境。流程是：生成首版 → 看视频 → 选定修改起点 → 描述修改 → 重新生成 → 比较与选择。继续使用现有视频权重，本轮没有新增训练。

## 怎么用

1. 生成首版，或在创作会话中打开已有结果。页面首次进入一个会话时，默认固定最近已完成视频作为编辑起点；用户明确选择的历史基线优先。
2. 在任意已完成视频卡片点击 **基于此版修改**。它只选编辑起点，不调用模型。顶部提示条说明实际编辑的是哪一版；下方浏览或对比其他版本不会偷偷更换它。
3. 输入修改要求，例如 **保持前进不变，先把视角左转再向右转**。
4. 点击 **仅预览修改计划** 查看按键、时间和保留范围，再确认生成；也可明确点击 **修改并生成新版本**，一次提交依次完成编排与生成。
5. 后者只会提交本次接口返回的明确版本，且该版本必须通过输入检查。需要澄清、模型失败或接口未给出版本时停止，不改用旧计划或最新计划，也不自动重试。
6. 新视频完成后，与参考版本并排播放；满意则选择该版，不满意则再次选定视频并描述修改。每次修改保留为独立版本，旧视频不覆盖。

“先向左看再向右看”和“前3秒前进，然后抬头3秒，其他不要动”示例按钮只填入文字，不会调用模型或生成。改动描述或编辑基线后，旧预览的生成按钮会禁用，直到重新编排。

## 指令如何落到视频

| 输入 | 当前控制含义与限制 |
|---|---|
| 保持前进不变，先把视角左转再向右转 | 保持原移动轨；镜头 J 前半段、L 后半段。未给时间时沿用 7.5 + 7.5 秒默认，页面明确披露 |
| 先镜头左转3秒再向右转2秒 | J 在 0–3 秒、L 在 3–5 秒；支持后一分句省略“镜头”主语 |
| 只在第8到10秒抬头，其他不要动 | 替换 I 控制轨为 `[8,10)`，其余按键逐帧不变；“抬头”指镜头俯仰，不是人物头部姿态 |
| 先左转再右转 | 没有明确人物移动还是镜头转动，要求澄清 |
| 再向山走一点再抬头 | 不假定山在前方；要求用户确认改写成明确的移动／镜头输入，不宣称知道到山的路径 |

时间按 16 FPS 编译为 240 个未来控制帧。“一点”没有标定成真实距离或角度。**保留输入不等于保留像素**：固定首图、场景提示词与 seed 重新生成整段后，人物和背景细节仍可能改变。

## 模型与程序各负责什么

- 本地 Qwen 模型提出控制计划；确定性检查器检查按键、时间顺序和未修改轨道。
- 明确的模型格式或计划错误最多反馈给模型一次，在同一模型加载中修订；仍不通过就停止。用户意图本身含糊时不靠重试猜测。
- 前端的一键按钮是用户明确授权的两个接口调用，不是模型自行决定启动任务。
- 视频生成后以人工回看和自然语言修改为主。视觉观察未达到可靠自动纠错标准，自动视觉修订保持关闭，不把模型判断当成视觉成功。

详见[有界计划修订](creator-plan-repair.md)、[精确时间线与版本基线](creator-timeline-edit.md)。

## 重新生成，不是末帧续写

当前每版都复用原首图重新生成约 15 秒。修改基线用于继承控制计划，不作为逐帧编辑素材，也不把旧视频末帧自动接到新视频开头。没有实现任意物体定点导航、人物骨骼控制、像素级局部保持或实时交互。

## 启动

沿用[Creator 部署说明](creator.md)，现有模型、场景文件和守卫配置均放数据盘，不写入公开仓库。例如：

```bash
python scripts/serve_creator.py \
  --deployment /DATA_DISK/creator/deployment.json \
  --provider-config /DATA_DISK/creator/provider.json \
  --serialize-model-and-video
```

服务保持 `127.0.0.1` 监听，通过用户自己的 SSH 转发访问。单卡部署串行加载语言模型和视频模型；每次 GPU 任务仍需已有明确授权、空闲卡检查、共享租约、剩余预算及有限时长。不要同时用两个服务持有同一任务根。

## 验证口径

CPU 与浏览器用例验证的是编辑起点、错误停止、旧计划防误提交及请求版本一致性，不代表模型泛化准确率或画质。实机结果另行记录，不能用历史视频或浏览器测试替身代替新生成。
