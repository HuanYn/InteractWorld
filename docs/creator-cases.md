# Creator 小型指令用例

这是一组人工编写、可逐条检查的 **规则/契约用例**，不是训练数据规模成果，也不是 Qwen、VLM、视频生成或世界任务完成率评测。脚本只调用当前 `training.creator.planner.plan_request`，不加载模型、不访问网络、不使用 GPU、不生成视频。

数据在 [creator_instruction_cases.json](../examples/creator_instruction_cases.json)，检查入口为 [check_creator_cases.py](../scripts/check_creator_cases.py)。数据与检查脚本本身不修改 planner 或 service，也没有新增 CI；下文单独记录规则词表修复前后的结果。

## 运行

```bash
python scripts/check_creator_cases.py
python scripts/check_creator_cases.py --output /path/to/new-report.json
```

标准输出先给简短 JSON 汇总，再给逐例表和失败原因。可选 `--output` 保存完整 JSON，含每例原始输入、预期、实际 planner 返回、各类错误；目标文件已存在时拒绝覆盖，重跑请使用新文件名。有任何契约错误、预期不匹配或保留失败时退出码为 `1`，全部通过为 `0`。因此下面记录的基线退出 `1` 是真实覆盖缺口，不应被脚本吞掉或改成成功。

## 数据与预期的含义

固定未来输入为 240 帧、16 fps，即 15 秒。这里的 timeline 不含起始 RGB 图像；不能把它与视频的 241 张 RGB 帧混为一谈。

| 控制组 | 键与含义 |
| --- | --- |
| 移动 | W 前进、A 左移、S 后退、D 右移 |
| 镜头 | I 抬头、J 左看、K 低头、L 右看 |

每例包含 `id`、`category`、`text` 和 `expected`。`expected.status` 明确为 `ready`、`clarify` 或 `unsupported`；有把握时另列 `edit_scope` 和完整 `action_segments`。`expected.preserve_keys` 是必须逐帧与旧计划完全一致的键，而不只是总持续时间一致。空列表表示该例没有额外的旧计划保留要求。

有局部编辑的用例通过 `previous_plan` 引用文件顶部的固定旧时间线。检查器会把它展开为实际 `previous` 参数传给 API，不先调用 planner 来生成“标准答案”。三个旧计划分别包含分段移动加后半段抬头、全程前进加后半段抬头、以及前进后抬头。

无明确时长的基础用例采用当前公开规则策略：单动作覆盖全程；两个先后动作各占 120 帧；“一直前进，后半段抬头”保留前进并叠加镜头。缩短默认减半并保留原开始时刻；延长默认增加原时长的一半、优先向后延伸，碰到末帧再向前扩展。这是控制输入约定，不是对所有自然语言表达的普遍正确解释。

32 条用例覆盖：

- 8 条单动作：每个 WASD/IJKL 控制键各一例，混合中文和英文。
- 4 条时段编排：先后动作、全程动作叠加、前半段、后半段。
- 7 条局部修改：镜头/移动分别缩短、延长、取消，以及替换镜头方向。
- 3 条歧义：未说明减少哪个动作、没有旧计划、未区分镜头与移动的转向。
- 3 条不支持目标：精确导航、攻击 NPC、切换新场景。
- 2 条冲突：同时前进后退、同时要求两类控制都保留但又修改。
- 3 条对抗输入：要求忽略约束、伪造保留声明并删除移动的提案、非整数帧数提案。
- 2 条自然说法：明确要求“时长减半”“时间增加一半”，用于暴露规则词表覆盖缺口。

带 `proposal` 的两例是人工构造的不可信外部提案，绝不是 Qwen 的实际输出。“攻击 NPC”属于当前不支持的世界动作；“忽略约束”属于输入约束绕过测试，两者不应混称为模型安全评测。

## 检查内容及边界

检查器在当前 planner 之外用少量独立逻辑核对返回字段、状态、整数帧数、总帧数、合法键、冲突按键和非 ready 的不可执行性。它也检查调用没有修改传入的旧计划/提案，并独立重算实际 `edit_scope` 的保留结果，不相信返回的 `preserved` 声明。

预期检查另外比较状态、指定的编辑范围，以及展开后的逐帧 timeline；等价的相邻分段写法不会造成假失败。局部保留检查采用用例明确给出的 `preserve_keys`，部分持续时间修改还要求除目标键外的所有键保持不变。

`not_executed` 表示没有可检查的 ready 时间线，**不计为保留成功**。例如恶意提案被拒绝是拒绝测试通过，但不等于执行了局部修改；自然说法意外返回 clarify 则仍算预期失败。只有 ready 时间线实际通过逐帧比较才计入 `preservation_pass`。

这个小集合并非随机抽样、独立留出集或统计 benchmark，且修复使用了已知失败。30/32 与 32/32 都只能称为这 32 条人工用例的规则/契约预期匹配结果，不能外推为自然语言准确率，更不是 Qwen 成功率。后续真实 Qwen 验证应单独记录模型、实际输入/输出及契约检查；VLM 观察和视频动作是否呈现也必须另给证据，不能复用这里的数字。
