# Creator 面试讲解提纲

当前状态（2026-09-25）：真实 Qwen 计划与局部修改、两版 GPU 视频生成已完成；原 worker 输入栏封装失败后通过 CPU 恢复，两任务状态为 `completed`，原失败证据保留。修改保持 W 输入240帧，将 I 输入从120帧缩短到60帧。真实视觉观察暴露出语义混淆和证据不足，当前降级为人工审核，人工评价尚未填写。视觉反馈修订默认关闭，画质、动作响应和反馈收益仍未验收。

## 一分钟介绍

InterActWorld 将首图、固定场景文本和按键时间线输入自训动作条件视频模型。Creator 增加自然语言编排、多轮局部修改和版本管理：语言模型提出计划，程序严格校验按键、时长与修改范围，再交给异步生成器执行。比如“保留前进，只缩短抬头”，需要逐帧证明移动输入没变，固定同一首图和 seed，重新生成可比较的版本。本轮真实两版视频已交付，但只读原视频的视觉评估出现不可靠判断，因此默认关闭视觉反馈修订并交给人工审核。代码保留可显式开启的最多一次修订机制，由人工触发生成和接受；没有做 RL，也没有验证自主改进收益。

## 核心代码链

`自然语言 → Qwen提案/明确标注的规则回退 → 严格计划校验 → 保存版本 → 异步执行 → 局部修改并生成对比版 → 原视频视觉观察 → 人工审核`。视觉反馈修订是默认关闭的可选分支，需显式 `--enable-visual-revision` 开启，且每个原始请求最多一次。

实际入口和启动命令见 [Creator 使用说明](creator.md)。实现的完整流程与当前跑通的阶段分开陈述；视频版本的“接受”不会由模型评分自动触发。

关键不是新增多少模型，而是计划、执行、观察和状态的边界：

- **计划不等于完成**：合法的240×8动作输入只能证明提交了什么，不能证明人物真的走到目标位置。
- **局部编辑约束**：将计划展开成240帧，逐帧比较未编辑类别；同一会话固定场景、首图、静态prompt和seed。
- **失败不推进成功状态**：每版绑定唯一生成任务，重复提交不重跑，失败版本不能被接受，旧结果不覆盖新请求。
- **同计划重试不重新规划**：执行或封装失败后，显式重试复用已校验计划，新建任务并保留旧证据；连续重试有上限。它不同于视觉不满意后的计划修订。
- **观察不偷看答案，但仍会误判**：视觉模型接收raw视频的8个真实时间点，不接收动作按键或HUD；本轮仍出现镜头与人物动作混淆，以及凭稀疏帧断言连续动作的情况。
- **修订默认关闭且有上限**：默认有效决策为 `ask_user`，保留原始模型决策、建议、JSON及降级理由。显式开启后每个原始请求最多一次视觉反馈修订；新用户编辑优先，人工评价不能被模型覆盖。人工触发新生成和最终接受。

## “走到桥边，再回头看山”怎么回答

先判断当前场景是否有可识别的桥、执行器是否有导航和人物朝向控制。这个版本没有三维地图、距离传感、目标导航或独立人物转身接口，不能把几个方向键解释成精确到达桥边。应澄清用户是否接受“向前移动一段，再旋转镜头观察山体”的近似镜头创作；不同意则明确不支持。若要可靠完成原任务，需要加入目标感知、可验证的状态/距离估计和分段闭环控制，再分别验证导航与生成器响应，而不是只改prompt。

## 怎样回答“这算 Agent 或 RL 吗”

可以称为有版本状态、工具执行和有限反馈的受限工作流：模型负责提出计划和观察建议，确定性代码校验并维护任务状态，用户控制生成与接受。这里没有奖励函数驱动的参数更新、策略训练或在线 RL。已有动作 Adapter/LoRA 的训练属于底层生成模型工作，不能把本轮调用语言模型和视觉模型写成新的 Agent RL 训练。

真正需要验证的是“修改后的真实视频是否更符合目标”，而不是模型是否输出了一个更高评分。应保留同首图、同场景、同 seed 的计划差异、原视频和人工判断。本轮视觉模型把摄像机抬头解释成角色头部动作，凭8帧断言末尾停止走动，并给出“增加抬头”却缩短时段的含糊建议；因此不继续视觉反馈修订，人工评价仍待填写。这些模型输出不能构成改进证据。

## 演示时拿出什么证据

先展示真实计划与局部修改：W 保持240帧，I 从120帧缩短到60帧；再展示与版本、任务 ID 对应的两段原视频和恢复后 `completed` 状态。两版原视频均为832×480、241帧、16 fps，API Range 请求返回 `206`。同时说明原 worker 的封装失败与后续 CPU 恢复，不将恢复成功说成首次执行成功；视频可播放和输入约束成立，也不等于动作命中或画质改善。

运行报告位置见 [Creator 验证状态](creator.md#验证状态)：工作区 `reports/interactworld-creator-20260925/`、离线对照页 `demo/index.html` 和服务端数据盘 `creator-runtime`。讲解应引用实际任务报告、媒体与观察记录，保留本次失败。原视频 worker 墙钟474.15秒和474.76秒包含预检与失败封装，CPU 恢复约5.8秒和5.9秒；不能将它们标为纯模型推理耗时。视频生成的精确模型耗时和峰值显存未知，13748 MiB 只是观测值。视觉检查 worker 另记58.72秒、peak allocated 9.22 GiB，不能转借给视频生成。不要拿旧样片或 CPU 测试数量代替本轮结果。

降级也有真实接口证据：`visual_revision_enabled=false`，有效决策 `ask_user` 与原 `model_decision=revise` 同时保留；请求修订返回 `400`，会话和队列没有变化。收束时 GPU 队列为空。本轮保守记账0.60782 GPU小时，存储保守上界399.933 / 400 GB，接近上限；不能把这次演示包装为可继续无限批量生成的服务。

## 不要声称

没有新增 Agent SFT/RL 训练，没有持久三维世界状态，没有可靠精确导航，没有实测实时性。CPU 单测通过不代表视频更好，模型评判也不是人工真值；原视频生成、完整交付、动作命中和反馈带来的改善是四个不同结论，分别需要证据。
